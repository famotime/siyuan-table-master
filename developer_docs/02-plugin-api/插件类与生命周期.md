- 适用版本：SiYuan `v3.7.3` / npm `siyuan@1.2.3`
- 最后核对：2026-08-02
- 稳定性：stable
- 权威来源：
  - <https://github.com/siyuan-note/petal/blob/main/siyuan.d.ts>

## 1. Plugin 核心生命周期

| 生命周期 | 用途 | 注意事项 |
|---|---|---|
| `onload()` | 注册命令、事件、顶栏、页签，加载配置 | 可以返回 Promise；避免长时间同步阻塞 |
| `onDataChanged()` | 插件数据在其他窗口或设备同步后发生变化 | 重新读取数据并更新 UI，不要假定只触发一次 |
| `onLayoutReady()` | 主界面布局与插件加载流程就绪 | 适合依赖布局、编辑器和 Dock 的后续逻辑 |
| `onunload()` | 禁用、重载或关闭插件时清理资源 | 解绑事件、停止定时器、关闭网络连接 |
| `uninstall()` | 插件被卸载时执行一次性清理 | 谨慎删除数据，必要时先确认或导出 |

### v3.7.3 的加载顺序

源码加载器会按以下顺序等待：

```text
await plugin.onload()
await plugin.kernel.init()
afterLoadPlugin(plugin)
plugin.onLayoutReady()
```

这意味着异步 `onload()` 完成前不会调用 `onLayoutReady()`；若插件包含内核插件，也会先完成 `kernel.init()`。不要再依赖旧版本中可能出现的竞态时序。

## 2. 常用实例能力

- `addTopBar()` / `addStatusBar()`：添加顶栏或状态栏元素。
- `addDock()` / `addTab()`：注册侧栏和自定义页签。
- `addCommand()`：注册命令面板命令与快捷键。
- `loadData()` / `saveData()` / `removeData()`：插件私有数据存储。
- `saveExportFile()`：保存插件生成的导出文件。
- `openSetting()`：打开插件设置界面。
- `getSecret()` / `getVariable()`：读取“密钥和变量”中的运行时值。
- `addAgentAction()`：为 AI 智能体注册前端动作。
- `kernel`：访问内核插件状态、RPC、批量调用等能力。

上述新能力已经由 `siyuan@1.2.3` 正式声明，不要额外使用 `declare module "siyuan"` 重复扩展。

## 3. 推荐生命周期模板

```ts
import { Plugin } from "siyuan";

export default class MyPlugin extends Plugin {
  private abortController?: AbortController;

  private onSwitch = (event: CustomEvent) => {
    console.debug("switch-protyle", event.detail);
  };

  async onload() {
    this.abortController = new AbortController();
    this.eventBus.on("switch-protyle", this.onSwitch);

    const settings = await this.loadData("settings.json");
    // 完成必要配置迁移；不要在这里执行长时间同步计算。
    console.debug("settings loaded", settings);
  }

  onLayoutReady() {
    // 依赖布局、编辑器或 Dock 的逻辑放在这里。
  }

  onunload() {
    this.eventBus.off("switch-protyle", this.onSwitch);
    this.abortController?.abort();
  }
}
```

## 4. `Plugin.kernel` 与 RPC 时序

当插件包实际包含内核插件 bundle 时，可以通过 `this.kernel` 使用内核能力：

```ts
this.eventBus.on("kernel-plugin-state-change", (event) => {
  console.debug("kernel state changed", event.detail);
});

if (this.kernel.state.code === 2) {
  const result = await this.kernel.rpc.call.example({ value: 1 });
  console.debug(result);
}
```

状态码 `2` 表示 `running`。RPC 在启动完成前可能返回 `-32002`，调用方应等待状态变化或提供有上限的重试。纯前端插件不要在 `plugin.json` 中声明 `kernels`。

## 5. 生命周期常见问题

- 在 `onload()` 中执行重同步逻辑，拖慢整个应用启动。
- 在模块顶层访问布局、活动编辑器或内核 RPC，导致启动竞态。
- 注册事件、定时器、观察器或网络连接后未在 `onunload()` 清理。
- 在 `onDataChanged()` 中无条件写回数据，形成同步循环。
- 配置结构升级时未保留版本字段和迁移逻辑。
- 把密钥写入日志、异常、DOM 或智能体结果。
