## 2. v3.7.x 需要重点关注的新事件

### `kernel-plugin-state-change`

内核插件状态包括 `inactive(-1)`、`ready(0)`、`loading(1)`、`running(2)`、`stopping(3)`、`stopped(4)`、`error(5)`。RPC 只应在 `running` 后调用；过早调用可能返回 `-32002`。

```ts
this.eventBus.on("kernel-plugin-state-change", (event) => {
  console.debug("kernel plugin state", event.detail);
});
```

### `switch-protyle-mode`

配合 `Protyle.switchMode` 使用。监听器不应持久保存已销毁的 Protyle 引用，并应在 `destroy-protyle` 或 `onunload()` 时清理关联状态。

### `code-language-update` / `code-language-change`

用于代码块语言工具栏和语言切换场景。事件负载可能随具体 UI 行为变化，必须使用 npm `siyuan@1.2.3` 中的 `IEventBusMap` 类型，不要只凭事件名猜测字段。

## 3. 已移除或替代事件

| 事件名 | 状态 | 替代方案 |
|---|---|---|
| `loaded-protyle` | 已移除 | 使用 `loaded-protyle-static` / `loaded-protyle-dynamic` |

## 4. 推荐监听模式

```ts
import { Plugin } from "siyuan";

export default class MyPlugin extends Plugin {
  private onSwitch = (event: CustomEvent) => {
    console.debug(event.detail);
  };

  onload() {
    this.eventBus.on("switch-protyle", this.onSwitch);
  }

  onunload() {
    this.eventBus.off("switch-protyle", this.onSwitch);
  }
}
```

- `on` / `off` 必须使用同一个函数引用。
- `ws-main`、搜索输入、编辑区点击等高频事件应节流或防抖。
- 不要在事件回调里执行长时间同步计算。
- 跨版本兼容时，以当前安装的 `siyuan` 类型和运行时能力探测为准。
